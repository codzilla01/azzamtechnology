# Azzam Technology

واجهة عربية وإنجليزية لمتجر أجهزة الكمبيوتر والشاشات واللابتوبات، مبنية بـHTML وCSS وJavaScript. تتضمن البحث والفلترة، والمفضلة والمقارنة والسلة، وتجميع PC، وإرسال تفاصيل الطلب عبر واتساب.

> **المتجر ما زال نموذجاً وليس متجراً جاهزاً للإنتاج.** تسجيل دخول الإدارة يتحقق على الخادم، لكن المنتجات والسلة والمفضلة وغيرها محفوظة في `localStorage` لكل متصفح؛ ليست بيانات مشتركة ولا يحميها خادم المصادقة. لا توجد قاعدة منتجات أو خدمة دفع أو إدارة طلبات على الخادم، ولا تنتقل المنتجات من جهاز الإدارة إلى أجهزة العملاء تلقائياً.

> **تنبيه أمني:** كان رمز بوت Telegram مكشوفاً في نسخة سابقة من الواجهة وتاريخ Git. حُذفت طريقة الدخول هذه من الكود، لكن يجب **إلغاء الرمز القديم من BotFather**؛ حذفه من الملفات لا يلغيه. لا يلزم إصدار رمز بديل لطريقة الدخول الجديدة.

## التشغيل محلياً والدخول الأول

يتطلب Node.js **22.x**:

```bash
npm ci
HOST=127.0.0.1 npm start
```

افتح `http://localhost:8000`، ثم اختر «دخول الإدارة» أسفل المتجر أو افتح `/admin.html`. عند أول تشغيل يُنشئ الخادم حساباً مؤقتاً فريداً:

- **اسم المستخدم الافتراضي:** `admin`.
- **كلمة المرور المؤقتة:** مولَّدة عشوائياً، وتوجد في ملف الخادم الخاص `~/.azzamtechnology/initial-credentials.json`. اعرضه محلياً باستخدام `cat ~/.azzamtechnology/initial-credentials.json`. لا ترفع الملف أو تشاركه علناً.
- عند أول دخول يجب تغيير كلمة المرور قبل فتح لوحة الإدارة، ويمكن تغيير اسم المستخدم أيضاً. يُحذف ملف البيانات المؤقتة بعد التغيير بنجاح.
- لاحقاً يمكن تغيير كلمة المرور أو اسم المستخدم من **الإعدادات ← بيانات دخول الإدارة** بعد إدخال كلمة المرور الحالية؛ اترك حقلي كلمة المرور الجديدة فارغين إذا أردت تغيير الاسم فقط. تغيير البيانات يلغي الجلسات الأخرى.

لحفظ الحساب في مكان آخر يمكن تعيين `AZZAM_AUTH_DIR` إلى مجلد خاص ودائم خارج المستودع وأدلة الملفات العامة قبل التشغيل. يحتوي `account.json` على تجزئة كلمة المرور لا كلمتها الأصلية. يحتفظ وضع الملف المحلي بالجلسات وتحديد المحاولات في ذاكرة عملية واحدة؛ إعادة تشغيل الخادم تنهي الجلسات. استخدمه لخادم Node واحد فقط، وليس لعدة عمليات أو وظائف خادمية مستقلة.

لا تستخدم `python -m http.server` أو فتح الملفات مباشرة لتشغيل الموقع: لا يطبّقان المصادقة على الخادم، وقد يكشفان ملفات المشروع. الخادم المرفق يعرض الملفات العامة فقط ولا يعرض `private/admin.html` إلا بعد تحقق الجلسة.

### تفاصيل الحماية وحدودها

- يُخزَّن ملح وتجزئة `scrypt` لكلمة المرور (للحسابات الجديدة: `N=32768, r=8, p=3`)؛ الجلسة عشوائية وصلاحيتها ٨ ساعات وتُرسل في cookie من نوع `HttpOnly` و`SameSite=Strict`، مع `Secure` في الإنتاج.
- تؤمّن الطلبات المغيّرة للبيانات بمطابقة `Origin` وطلب JSON، ويُحدّ الدخول إلى ٦ محاولات خلال ١٥ دقيقة لكل عنوان IP؛ كما يلزم تأكيد كلمة المرور الحالية لتعديل بيانات الدخول.
- اسم المستخدم من ٣ إلى ٣٢ حرفاً إنجليزياً أو رقماً، مع السماح بالنقطة والشرطة والشرطة السفلية بعد الحرف الأول. كلمة المرور ١٢ حرفاً على الأقل وبحد أقصى ٢٥٦ بايت؛ استخدم كلمة فريدة وطويلة.
- خيار الدخول المطبّق هو اسم المستخدم وكلمة المرور **فقط**؛ بصمة الجهاز غير مدعومة. لا توجد واجهة استعادة عبر البريد؛ استعادة الوصول تتطلب مسؤول الخادم والتخزين.
- للإنتاج يجب استخدام HTTPS وإعادة توجيه HTTP إلى HTTPS من الوسيط قبل عرض أي نموذج دخول. عند استضافة Node خلف وسيط عكسي موثوق، شغّل `NODE_ENV=production` و`AZZAM_TRUST_PROXY=1`، واجعل الخادم يستمع محلياً خلف الوسيط. يجب أن يحتفظ الوسيط بترويسة `Host` الأصلية، وأن يحذف ترويسات العميل `X-Forwarded-Proto` و`X-Real-IP` ويضبطهما بنفسه؛ لا تفعّل الثقة بالوسيط مع إمكانية الوصول إلى Node مباشرة. HTTPS ونسخ احتياطية آمنة ومراقبة الخادم تظل مسؤولية المستضيف.

## النشر على Vercel

الاستضافة الثابتة وحدها لا تكفي. الإعداد المرفق يبني `public/` من قائمة ملفات عامة فقط ويستخدم وظائف Node للمصادقة وعرض الإدارة. **يلزم تخزين Redis دائم مشترك عبر REST** (مثل Upstash Redis مع دعم أوامر `SET NX` و`EVAL`) لحفظ الحساب والجلسات وتحديد المحاولات بين الوظائف؛ لا تستخدم نظام ملفات Vercel المؤقت لهذا الغرض.

قبل النشر، أضف في إعدادات بيئة Vercel، دون وضع القيم في Git أو الواجهة:

| المتغير | الغرض |
| --- | --- |
| `AZZAM_REDIS_REST_URL` | عنوان HTTPS لواجهة Redis REST. |
| `AZZAM_REDIS_REST_TOKEN` | رمز Redis REST السري على الخادم فقط. |
| `AZZAM_INITIAL_ADMIN_PASSWORD` | كلمة مرور مؤقتة قوية وفريدة، لا تقل عن ١٢ حرفاً، لتهيئة الحساب الأول مرة واحدة. |
| `AZZAM_INITIAL_ADMIN_USERNAME` | اختياري؛ الافتراضي `admin`. |
| `AZZAM_AUTH_NAMESPACE` | اختياري؛ بادئة مفاتيح المصادقة، وافتراضياً `azzam-admin`. |

تُقبل أيضاً متغيرات Upstash القياسية `UPSTASH_REDIS_REST_URL` و`UPSTASH_REDIS_REST_TOKEN` أو متغيرات Vercel KV القديمة `KV_REST_API_URL` و`KV_REST_API_TOKEN`. بعد تهيئة السجل في Redis تُتجاهل متغيرات الدخول الأول ولا تعيد تعيين الحساب؛ غيّر كلمة المرور من الشاشة الإجبارية ثم احذف متغير كلمة المرور المؤقتة من إعدادات النشر. استخدم قاعدة Redis ومفاتيح منفصلة للإنتاج والمعاينات لتجنّب مشاركة الحساب أو الأسرار مع فروع غير موثوقة.

يتولى `vercel.json` تنفيذ `npm run build` وتحديد `public/` كدليل الملفات العامة وتوجيه `/admin.html` إلى وظيفة محمية. لا تغيّر دليل الإخراج إلى جذر المشروع. بعد النشر اختبر أن `/private/admin.html` غير متاح، وأن `/admin.html` يطلب تسجيل الدخول من متصفح جديد. إذا لم تُضبط Redis أو تعذّر الوصول إليها، تفشل المصادقة بشكل مغلق وتظهر رسالة عدم توفر الخدمة؛ لم يُنشأ حساب سحابي أو تُضبط قاعدة Redis تلقائياً بواسطة هذا المستودع.

## اللغات وبيانات المنتجات

- العربية هي اللغة الافتراضية. استخدم زر `EN` / `عربي` في المتجر أو المساعد أو الإدارة للتبديل؛ يتغير الاتجاه تلقائياً، ويُحفظ الاختيار في `localStorage` ويُزامَن بين تبويبات الموقع.
- تترجم الواجهة والرسائل المدمجة محلياً في `i18n.js`. إجابات المساعد المخصصة التي يكتبها المسؤول تظل كما أُدخلت ولا تُترجم تلقائياً.
- يمكن إدخال اسم المنتج ووصفه ومواصفاته بالإنجليزية اختيارياً؛ تتطلب كل مواصفة مترجمة اسماً وقيمة أصليين. عند غياب الترجمة يُعرض الأصل، ولا تتغير المنتجات الموجودة تلقائياً. يشمل البحث البيانات الأصلية والترجمات، وتُضمَّن الترجمات في التصدير والاستيراد.
- مسح بيانات المتصفح يزيل تفضيل اللغة وبيانات المتجر المحلية. عند عدم وجود منتجات يعرض المتجر حالات فارغة بدلاً من أسعار أو منتجات وهمية. الخطوط والأيقونات مستضافة محلياً داخل `assets/vendor` مع تراخيصها.

## الاختبارات

```bash
npm ci
npm run test:auth          # اختبارات الخادم والتخزين والجلسات والأمان
npx playwright install chromium
npm test                   # اختبارات الواجهة والتسجيل واللغات والتسوق
npm run build              # إنشاء حزمة الملفات العامة للنشر
```

تستخدم اختبارات الواجهة حساباً مؤقتاً ومعزولاً، وتغطي الدخول الأول وتغيير البيانات والخروج، إلى جانب اللغتين والمنتجات والبحث والسلة والمساعد. تشمل اختبارات الخادم محاكاة Redis مشترك؛ يلزم اختبار الاتصال بخدمة Redis الفعلية بعد إعداد النشر.

## أفكار التطوير التالية

1. إنشاء API وقاعدة منتجات ومخزون مشتركة مع صلاحيات وسجل أمني ونسخ احتياطية.
2. إضافة ترتيب المنتجات وفلاتر المواصفات وصفحات التفاصيل والروابط القابلة للمشاركة.
3. بناء خطوات للعنوان والشحن والتأكيد، ثم ربط بوابة دفع وتتبع الطلبات عند توفر البنية الخلفية.
4. التحقق من توافق قطع التجميع واقتراح بدائل مناسبة للميزانية.
5. عرض معلومات ضمان وشحن موثقة وإضافة التحليلات بعد توفير سياسة خصوصية وموافقة مناسبة.
